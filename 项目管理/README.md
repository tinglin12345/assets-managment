## 改完怎么回到页面

正本在 `story-cards/`。改完在工作目录（`资产管理/`）跑：

```bash
python3 .patch-story-cards.py        # 把卡、估算、面板注入 CKFM_asset_blueprint.html
node .build-share.js                 # 重建业务评审只读版 review.html
node .run-all.js                     # 38 项测试 ＋ 20 项校验，必须全过
```

再把 `CKFM_asset_blueprint.html` → 仓库根目录的 `index.html`、`review.html` 覆盖掉，提交推送。

## 估算口径

档位固定：设计 0 / 0.5 / 1 / 2 人天，开发 0.5 / 1 / 2 / 3 / 5 / 8 人天。两条规则：

1. **增量原则** —— 一族卡里第一张吃掉引擎成本，后面的只记增量。
   例：导入引擎在 US-MAIN-07／08 记 8＋8，S4／S5／S6／S7 复用它，只记各自多出来的部分。
2. **接口只建一次** —— IoT／泛微／GSS／维保／CAT1 各只有一张卡记 5，别处引用记 0.5～2；
   通知渠道平台在 US-A4-01 建，各处调用 0.5。

人天＝一个人干一天，不是日历天；开发含前后端，不含测试、UAT、联调等待、返工与审批等待。
这是 BA 初估，点数由开发团队在 Sprint Planning 校准。
