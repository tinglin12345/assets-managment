# 项目管理

这个文件夹放**项目本身**的东西：流程拆解的结论、用户故事卡、估算与排期。
仓库根目录那两个 HTML 是给人看的**页面**（线上链接指向它们），两者分工不同。

## 先看这两份

| 文件 | 看什么 |
|---|---|
| [概览.md](概览.md) | 项目多大、12 个模块各要多少人天、按依赖顺序排下来多久、风险在哪 |
| [用户故事拆卡.md](用户故事拆卡.md) | 全部 277 张卡：角色、Epic、故事陈述、验收标准、待确认、估算 |

还有 [流程变更说明.md](流程变更说明.md)：和业务流程图原图相比，哪里改了、哪里还没定。

要交互地看（推荐）：打开仓库根目录的 `index.html`，每张流程图右上角有
**用户故事拆卡**和**时间线总览**两个入口 —— 面板里能改设计／开发人数当场重算工期，
也能按角色、Epic、流程顺序三种方式分组看卡，每张卡可以一键定位回泳道里对应的那一步。

## 目录

```
概览.md                 模块排期总览（生成物，勿手改）
用户故事拆卡.md          277 张卡全文（生成物，勿手改）
流程变更说明.md          和原图的差异、待确认清单（生成物，勿手改）
story-cards/
  用户故事拆卡-数据.js    正本：角色、Epic、故事、验收标准、待确认、优先级
  用户故事拆卡-估算.js    正本：每张卡的设计／开发人天
  用户故事拆卡-面板.js    蓝图里那个面板的实现
```

前三份 md 都是生成物 —— 手改会在下次生成时被覆盖。要改内容，改 `story-cards/` 里的正本。

## 数字从哪来

- 本期 266 张卡（另有 11 张不在本期：GSS 自动对接的未来方案、标了（待废弃）的卡）
- 设计 139.5 人天 ＋ 开发 578 人天 ＝ **717.5 人天**
- 按设计 1 人、开发 2 人的流水线排，**约 62 周（14.3 个月）**；完全串行 85.7 周
- **不含**测试、UAT、联调等待、返工与审批等待 —— 按经验再加 30%～50%

档位固定（设计 0/0.5/1/2，开发 0.5/1/2/3/5/8），并遵守两条规则：一族卡里第一张吃掉引擎成本
（增量原则）、外部接口只在建接口那张卡上记成本（接口只建一次）。
这是 BA 初估，点数由开发团队在 Sprint Planning 校准。

## 改完怎么同步

正本在 `story-cards/`。改完回到工作目录（`资产管理/`）跑：

```bash
node .gen-story-md.js 项目管理      # 重新生成 概览.md 与 用户故事拆卡.md
python3 .patch-story-cards.py       # 把卡与面板注入蓝图 HTML
node .build-share.js                # 重建 review 版
node .run-all.js                    # 38 项测试 ＋ 20 项校验，必须全过
```

然后把新的 `CKFM_asset_blueprint.html` → `index.html`、`review.html` 复制进仓库，
**并在根目录 [变更记录.md](../变更记录.md) 里加一条**（这是约定，不是可选项）。

## 不进这个仓库的东西

需求书 PDF、会议记录、业务流程图原图（公司内部材料），以及本机那几百个补丁与回归脚本
（只对本机有意义）。根目录 `.gitignore` 用白名单挡着。
