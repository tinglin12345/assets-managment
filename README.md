## 页面里有什么

- **12 个流程阶段、50 个场景**的端到端服务蓝图：角色行为、前端触点、后台处理三排泳道，
  判断菱形可点进对应的分支场景。
- **用户故事拆卡**（每张流程图右上角）：277 张卡，按 角色 → Epic → Story 三层组织，
  每张卡有验收标准、待确认事项、优先级，以及设计与开发的人天初估。
  点一张卡能定位回泳道里对应的那一步。
- **时间线总览**（同一位置的第二个按钮）：12 个模块按依赖顺序排的排期甘特图，
  可以改设计／开发人数当场重算工期，可切「只看本期」。
  当前口径：本期 266 张卡 ＝ 设计 139.5 ＋ 开发 578 ＝ 717.5 人天，
  设计 1 人、开发 2 人约 62 周（不含测试、UAT、联调等待与返工）。
- **角色视图、工单泳道、状态 × 任务对照**：点任意角色胶囊或任务标进去看。

## 仓库里的东西

```
index.html              完整版（线上）
review.html             业务评审只读版（线上）
项目管理/
  流程变更说明.md        和业务流程图原图相比，哪里改了、哪里还没定
  story-cards/          故事卡正本：数据、估算、面板实现
```

故事卡与估算的正本是 `项目管理/story-cards/` 里那两个 `.js`；页面里的卡是由它们注入的，
改完在工作目录跑 `python3 .patch-story-cards.py` 重新注入，再跑 `node .build-share.js` 重建评审版。
